# PixelMC Manager 插件页面风格规范

更新时间：2026-10-26。适用于 MemorialTitles、DailyFortunes 及以后所有 Manager 插件网页。

## 1. 基准、范围与使用方法

**插件以当前修订后的 MemorialTitles 页面为基准，不照搬 Manager 本体的卡片仪表盘。** 本文包含本轮全部确认的通用规则与插件例外；用户后续明确决定优先，修改时必须同时更新本规范和验收记录。

开始新插件前，先读本文，再对照 Titles 的列表、玩家、操作记录、设置、详情各一页。使用现有组件和样式，只有业务专属内容才新增组件。完成后逐项执行第 10 节，不以“风格差不多”代替验收。

规范描述目标，不表示所有正式服务已经升级。当前新增交互在隔离本地预览中验证；正式接入边界见第 11 节。

## 2. 页面骨架与插件标识

- 侧栏插件一级名称优先四个汉字，如“称号管理”“抽签管理”；点击展开/收起二级页面。
- 侧栏品牌保持 PixelMC Manager 单行。进入插件后第二行显示插件英文名，字体沿用原 Manager 副标题，不加粗。
- 页面主标题右侧统一使用细竖线 + 低强调英文插件名：`称号档案 | MemorialTitles`、`玩家签历 | DailyFortunes`。复用 `title-line`、`server-name`，不要自行画另一套样式。
- 标题下只留一句说明。删除“纪念称号 / 独立称号资料库 · 收藏跨整合包保留”这类重复横栏，不额外占一行。
- 顺序：标题与说明 → 分类标签/主操作 → 搜索 → 表头 → 内容 → 分页。占满可用内容宽度，不在列表两侧加入多余空白。
- 深浅主题结构相同。继承主题变量与既有字体，不硬编码另一套背景、字体或浅色文字黑底。

## 3. 标签、数量与密度

- 真正的页面分类、设置分类、详情分类和预览分类均为透明底标签；选中项文字高亮，底部 2px 强调色细线。禁止块状选中背景、胶囊底色。
- 标签间距约 24px，12px 文字；导航条约 48px 高，尺寸以共享 CSS 为准。窄屏允许换行，不溢出遮住操作。
- 有明确总量的**列表分类**在标签后显示小号数量，约 10px、muted、常规字重，间距 7px；0 显示为 0，未知显示“—”，不能把未知当 0。
- 数量来自完整分类，不是当前页行数；默认不受搜索关键词影响。特定玩家历史的数量属于该玩家范围。分类切换、搜索后重置分页。
- 表单页、详情编辑页无集合语义，不强加数量。例：基本资料、文字样式、每日抽签。
- 列表密度按钮直接切换“舒适／紧凑”，有线性图标和按下状态；不再做“显示”下拉菜单。
- 称号档案移除旧“筛选”按钮；可见性属性本身保留，可在详情编辑。不要悄悄保留已隐藏的筛选条件。

## 4. 列表、表头与排序

| 项目 | 规则 / 复用位置 |
| --- | --- |
| 表头底色 | `listChrome.css` 的 `--table-heading-bg`：深色 #1e1e20，浅色 #f5f5f7，整行铺开 |
| 表头高度 | 约 39px，11px muted 文字，细分隔线 |
| 搜索行 | 约 49px，左右 30px；无大块输入卡片 |
| 舒适列表 | 约 72px；紧凑约 48–58px，沿用各行已有内容结构 |
| 列表边距 | 内容左右约 30px；窄屏沿用共享 19px/16px；表头背景与行分隔线贯穿列表 |
| 分页 | 底部约 45px；总数在左，页码与前后箭头在右；有边界禁用状态 |

- 档案主名称下一行只显示创建日期，如 `2026-10-26`，**不加“创建于”**，不暴露内部 ID。玩家 UUID 是明确需要的信息，不属于应隐藏的内部档案 ID。
- 玩家“最近登录”、签历“最近抽签”、操作时间均显示日期和时分，不仅显示某天。按真实时间戳排序，不用日期字符串或午夜补造时刻。时区应明确且一致；当前预览用 Asia/Shanghai。
- 可排序表头有低强调方向图标，选中时强调；首次点击升序，再点降序。文本按拼音/字母、数值按数值、时间按时间戳。空值始终最后；相同值有稳定名称/ID 次序。
- Titles 玩家：玩家名、收藏数量、当前佩戴称号名称、最近登录可排序；排序完整集合后再分页。当前佩戴按展示名，不按称号内部 ID。
- Titles 档案：称号名、拥有者数量、分类、来源、绝版状态、图鉴可见性可排序；默认创建时间新到旧。状态分组同组按名称稳定排序。“操作”列不可排序。
- **操作记录是例外：始终最新在前，时间是普通表头，无排序按钮、箭头或反向选项。**
- 禁止只排序/过滤当前页，禁止为取得数量把全部数据库记录下载到浏览器。

## 5. 插件玩家身份（与 Manager 本体不同）

- 插件玩家分类固定“全部玩家 / 在线玩家 / 离线玩家”，三个标签各自显示完整总数。
- 行内为左侧原版皮肤头像（含帽子层），右侧第一行“小状态点 + 游戏内名字”，第二行 UUID；字体、对齐、间距复用 Titles 的 `player-link` / `player-identity`。
- 状态点在名字前，不在头像外侧；在线绿色，离线低强调灰色，约 5px。不新增独立“在线状态”列，不在每行重复写“在线/离线”。读屏标签仍须提供状态。
- **Manager 本体仍可保留独立状态列及较大点；不得为统一插件而改掉本体。**
- 默认在线在前，同组 A–Z/拼音。在线优先与离线优先切换只反转组序，同组始终 A–Z。其他列排序按该列实际值执行。
- UUID 容得下就完整显示，放不下省略并可查看完整值；不要固定只显示几个字符。
- 离线资料和头像保留；真实接入只登记成功登录的真人，过滤假人；头像优先 Mojang 原版，后台异步刷新，失败使用缓存/默认头像，不阻塞登录。这不是预览头像已接入的声明。

## 6. 操作记录

- 顶部分类标签使用第 3 节设计，数量遵守同一口径。分类按业务定义，不强制所有插件用完全相同的文案。
- Titles：全部记录、发放与撤销、称号编辑；DailyFortunes：全部记录、签文编辑、抽签设置、签笺补领、撤回操作。
- 每条操作文字前都有 16px 低强调历史图标 `ClockCounterClockwise`，间距约 10px。撤销、删除文字保留警示颜色，图标不抢色。
- 对象主信息在上，说明在下；管理员/操作者、完整时间按列对齐。
- 点击打开右侧详情。前后值纵向排列，中间向下箭头。
- 撤回只撤一项改动，涉及字段存在后续变更时提示冲突；不以整库快照回退替代单项撤回。

## 7. 设置与数据页

- 设置页复用 Titles：`view-bar` / `view-tabs` → `settings-scroll` → `settings-content` → `settings-section`。不使用 Manager 首页那种四张大边框卡片布局。
- 分类分离业务；DailyFortunes 为每日抽签、收藏展示、数据配置。切分类不丢未保存草稿，离开页面有未保存保护。
- 用分区标题、短说明、细分隔线组织表单。主要设置在左，确有意义的预览/签池统计可在右，使用 `settings-layout`；窄屏上下排列。
- 表单使用共享 `Switch`、`Select`、取色器和按钮，不保留浏览器原生下拉、取色器外观。
- 保存状态与按钮使用 `settings-save`：左侧显示“当前设置已保存 / 有未保存的修改”，无修改时禁用保存。抽签设置右侧只保留“保存设置”，不放“还原修改”。不要用“仅影响本地预览”代替保存状态；本地模拟提示集中在页面顶部，真实接入状态仍如实显示。即时操作的数据页不展示无意义的“保存设置”。
- 数据配置参照 Titles 数据备份页：完整备份标题/说明 + 右侧主按钮；下方备份列表、验证/预览、下载和校验文件；再下方配置导出、导入、重载操作块；最后数据库状态模块。
- 数据库状态仅出现在“数据备份 / 数据配置”分类，展示设置、首登奖励、每日抽签、收藏展示不重复显示。
- 状态卡片必须放在同一个 `settings-content` 内，复用 `database-card settings-database-card`，左右与上方配置操作对齐、宽度一致；卡片自身外边距为 0。分隔线上下沿用分区的 28px / 27px 间距（1px 边线计入后视觉等距），不得再叠加容器底部 padding 和额外 top margin，造成双倍空白。页面末尾保留正常容器内边距，不用拉伸空区填满屏幕。
- 数据库模块复用 `database-card`，含图标、实际连接状态、最近成功时间（若已知）和版本信息。未接入写“未连接”；本地模拟不得伪称数据库已连接或已完成异地备份。
- 备份保留策略、导入、重载等只有接口实现后才启用。原型可提供明确标记的本地备份/导出，不把原型按钮当服务器成功证明。

## 8. 详情、滚动条与动效

- 复用 Titles 的 `Modal`、`editor-header`、`editor-body`、`editor-footer`，不要新造更宽抽屉容纳预览。
- 插件宽详情 590px，<=760px 时 530px，<=540px 时填满可用宽；保留 10px 圆角、完整细边框、8px 外边距。Manager 核心抽屉外观同款但保留原有宽度。
- 预览减少空白背景、容器内边距；仍装不下时文字与美术一起等比缩小，不能只缩图片。
- 所有列表、抽屉、编辑区、设置页、弹出选项均用约 6px 主题滚动条、透明轨道、圆角滑块，隐藏上下箭头；检查嵌套容器，不能漏回原生粗滚动条。
- 插件进入：主品牌上移约 8px，插件名从右淡入伴短暂拖影；退出反向。插件到插件：旧名向左淡出，新名同时从右滑入，主品牌保持抬起。插件内切页不重播。
- 动画短促约 150–360ms，无持续拖影/发光；尊重减少动态效果设置。已存在的分段滑块使用快速滑动指示器，不能把这种滑块样式误用到插件分类标签上。

## 9. DailyFortunes 明确例外

- 签文美术背景、悬浮信息、物品 lore、日历为业务专属设计，允许专门布局；其外框和管理控件仍守通用规范。
- 签文档案不显示独立签号列，默认等级由高到低，同等级按题名拼音；反转等级只反转等级组。内部签号可保留在详情与游戏 lore。
- 日历在上、当前签预览在下，避免撑宽详情。通常五周；只有容纳该月全部日期必须时显示第六周，不能丢日期。
- 日期格右下半区以签等级颜色表示，中间斜向柔和渐变，不用难辨的小圆点或硬切三角；空格使用半透明签图案。
- lore 的诗句、解签淡灰；“第三签 · 上上签”按等级配色；归属/日期金色，玩家名黄色；管理 UI 不把整段文字渲染得花哨。

## 10. 新插件交付验收（逐项记录结果）

- [ ] 页面标题带正确英文插件名，无冗余横栏；侧栏层级及跨插件动效一致。
- [ ] 所有主标签、详情标签均是透明底细下划线；适用列表有全量计数，零与未知区分。
- [ ] 列表满宽，表头主题色/行高/边距/分页对齐；名称下日期无“创建于”和内部 ID。
- [ ] 玩家三分类齐全，离线头像保留；名字前小点、UUID 下置，无独立状态列。
- [ ] 验证文字/数值/时间正反序、同值与空值、跨页排序、过滤分页、在线分组反转；不能只看箭头变了。
- [ ] 操作行有历史图标，固定最新在前，无时间排序控件；详情/撤回保持原语义。
- [ ] 设置为 Titles 分区表单，数据库状态仅在数据分类出现；逐一切换全部设置标签确认。
- [ ] 表单状态实际反映已保存/未保存，抽签设置无“还原修改”按钮；未修改时保存禁用，修改后可保存，保存完成后恢复已保存状态。
- [ ] 数据页状态卡片与配置区同宽、左右对齐，分隔线上下约 28px 等距，无重复 padding/margin 形成的双倍空白；不存在未接入却显示成功的状态。
- [ ] 每个实际滚动区域检查细滑块/无箭头；抽屉不超宽、不遮挡页脚，预览等比缩放。
- [ ] 深色、浅色、窄屏和长名字/UUID、空列表/0/未知/断连状态都查看；键盘焦点可见。
- [ ] 本地预览与正式依赖隔离；保留用户草稿/示例，不为了截图重置数据。
- [ ] 前端构建通过；涉及数据行为跑针对性验证；保存代表截图，与 Titles 对照后再交付。

## 11. 代码复用与正式合并清单

- 共享主题与表格外观：`src/styles.css`、`src/layout.css`、`src/listChrome.css`。
- 插件组件：`src/titles/ui.jsx`（Modal、Select、Switch、Pagination）、`src/titles/SortLabel.jsx`、`src/titles/module.css`。
- 完整集合排序：`src/titles/sorting.js`；DailyFortunes 原型例外位于 `src/fortune-preview/`。
- MemorialTitles 0.4.2-dev 正式源码已实现离线、新排序与计数，真实 HTTP / MariaDB 本地验收已通过，尚未部署。接口接受 `presence=all|online|offline`、`sort`、`direction`，返回 `presenceCounts={all,online,offline}`；不可只发布前端后声称接口已完成。
- Titles 历史计数需接口返回当前玩家范围的 `categoryCounts`，不受搜索词影响。没有计数显示“—”；离线或新排序碰到旧接口明确报升级提示，不静默展示错误结果。
- UI 更新按归属打包：Manager 独立网页服务、MemorialTitles 独立网页资源及需要时的嵌入 JAR。原型改好不等于正式 JAR、数据库或服务器已部署。
- 本轮正式接入已迁移接口并同步独立网页资源；精确验收与部署边界见 ui-integration-20261026.md。源码提交不代表服务器部署。

## 12. 验收记录与维护门槛

新插件交付时按第 10 节逐项填写：页面/状态、复用组件、检查结果、截图或测试证据、未完成项。结果只能写“通过 / 失败 / 未验证 / 不适用（理由）”；未验证不能勾选通过。先完成一个代表列表、玩家详情、设置/数据页供对照，再扩展其他页面，避免复制错误骨架。

后续反馈应修订所属规则并增加检查项，而不是只追加一句“保持统一”。通用差异优先修共享组件；业务例外记入第 9 节并注明适用插件。规范不能替代实际验收，存在失败项时先修复，不能声称全部完成。
